# Keychron Q14 Pro — нативный конфигуратор для Linux

Полная замена браузерному Keychron Launcher и VIA. Работает напрямую с
клавиатурой через `/dev/hidraw` по протоколу VIA raw HID. Без браузера, без
Electron, без драйверов.

## Запуск

```bash
cd ~/projects/keychron-via
./keychron-q14.py
```

Или из меню приложений KDE: **Keychron Q14 Pro**.

## Что работает

| Функция | Статус |
|---|---|
| Чтение карты клавиш (4 слоя × 114 клавиш) | ✅ |
| Переназначение любой клавиши в EEPROM | ✅ проверено |
| Нажатие ручки энкодера | ✅ отдельная ячейка матрицы (0,0) |
| Повороты энкодера (по/против часовой) | ✅ проверено |
| Бэкап / восстановление (keymap + энкодеры + макросы) | ✅ |
| Переподключение USB (выход из зависания) | ✅ кнопка ⚡ USB |
| Определение активного слоя | ✅ переключатель Win/Mac + авто-выбор слоя |

## Энкодер: три независимых действия

У Q14 Pro ручка — это **три** разных назначения, не одно:

| Действие | Где хранится | Команда |
|---|---|---|
| нажатие (сейчас Mute) | ячейка матрицы `(0,0)` | `0x13 set_buffer` |
| поворот по часовой | слот `encoder[layer][0][cw=1]` | `0x15` (6 байт) |
| поворот против часовой | слот `encoder[layer][0][cw=0]` | `0x15` (6 байт) |

В приложении они в отдельном блоке «энкодер»: выбери цель
(нажатие / ↻ / ↺), затем жми код в палитре.

**Важно:** команда `0x15` в протоколе VIA — **ровно 6 байт**:
`[0x15, layer, idx, clockwise, kc_hi, kc_lo]`. Если пропустить байт
`clockwise`, прошивка сдвинет поля и запишет мусор (`0x00AA` → `0xAA00`) —
именно так ломался энкодер громкости.

## Дефекты прошивки (проверено на железе, V1.01)

1. **Зависание на некорректном запросе.** `0x12 get_buffer` с `size > 32`
   и `0x14 get_encoder` с `idx > 0` уводят прошивку в HardFault
   (вектор `0x080002DF` → `b .`). Устройство перестаёт отвечать,
   `dmesg`: `can't set config #1, error -32`. Лечится только
   переподключением USB (кнопка ⚡ USB) или физическим перетыком.
   В `via.py` эти запросы заблокированы на уровне проверок.
2. **Смешанный порядок байт.** `0x01` (protocol_version) отвечает
   big-endian, `0x0D` (macro_buffer_size) — little-endian.
3. **Неполный `0x02 get_keyboard_value`** — нет sub-команды `uptime`,
   которую требует VIA v3.
4. **Нет проверки границ** — `0x04` со слоем вне `0..3` возвращает
   `0x0000` вместо ошибки.

## Слои: какой править

Слои идут парами по переключателю ОС на задней панели:

| Переключатель | Рабочие слои |
|---|---|
| Win / Android | 2 (базовый) и 3 (Fn) |
| Mac / iOS | 0 (базовый) и 1 (Fn) |

Приложение стартует на активном слое и помечает неактивные предупреждением.
Правка не того слоя — самая частая причина «настройки не применяются»:
клавиша записывается в EEPROM, но устройство её не использует.

## Структура

```
keychron-q14.py   — GTK4-приложение (визуальная карта + палитра)
via.py            — клиент VIA-протокола через /dev/hidraw
keycodes.py       — таблица QMK/VIA keycode'ов и их названий
kle.py            — парсер KLE-раскладки (координаты, повороты)
q14_pro.json      — официальный VIA-definition от Keychron (6×19, 4 слоя)
backups/          — JSON-бэкапы (keymap + энкодеры + макросы)
```

## Геометрия

- Матрица: **6 строк × 19 столбцов**, из них 105 клавиш на раскладке
- Байт на слой: **228** (114 ячеек × 2 байта), слоёв **4**, всего **912 байт**
- Порядок байт в keymap: **big-endian** (старший байт первым)

## CLI (без GUI)

```bash
./via.py info                        # параметры клавиатуры
./via.py dump backups/my.json        # полный бэкап
./via.py restore backups/my.json     # восстановление
./via.py get 0 1 1                   # прочитать keycode
./via.py set 0 1 1 0005              # записать keycode (A -> B)
./via.py enc 0 0                     # прочитать энкодер слоя 0
```

## Важно про транспорт

Прошивка Keychron присылает ответ на **каждую** команду, включая
set-команды. Если их не вычитывать из `/dev/hidraw`, следующий запрос
получит чужой (устаревший) ответ — и результат будет случайным. Именно
поэтому `via.py`:

1. очищает буфер перед каждой командой (`_flush`);
2. проверяет, что первый байт ответа совпадает с кодом команды.

Без этой проверки настройки «не применяются» и значения читаются неверно.

## Требования

- Права на hidraw: `/etc/udev/rules.d/50-keychron-qmk-via.rules` (уже есть,
  режим `0666` для VID `3434`)
- Python 3 + PyGObject + GTK4 + pycairo (всё установлено)

## Восстановление после сбоя

Если карта повреждена, есть два пути:

```bash
# 1. Из бэкапа (сохраняет пользовательские назначения)
./via.py restore backups/<файл>.json

# 2. Заводской сброс (стирает всё пользовательское!)
python3 -c "import sys; sys.path.insert(0,'.'); import via; via.Via().call([0x06])"
```
